# 文档检索

## 模块作用

`retriever/` 负责把文档和用户查询变成可比较的表示，并从 Milvus 找到与查询相关的文本块。它处于文档加工和答案生成之间：入库时接收已解析切分的内容，提问时根据查询返回候选内容。

## 入库与查询

```text
入库：文本块 → embedding → 写入 Milvus
查询：用户问题 → embedding/稀疏表示 → Milvus 检索 → 返回候选 Chunk
```

稠密向量适合匹配语义接近但用词不同的内容；稀疏检索能更好保留关键词、编号和专有名词的匹配信号。混合检索组合两类信号，之后可由重排器进一步精排。

## 文件职责

- `base.py` 定义检索接口，使上层编排不必依赖每个存储实现的内部方法。
- `embedding.py` 加载嵌入模型，计算文档和查询所需的向量或稀疏表示。模型版本和向量维度必须与 Milvus 中已有数据匹配。
- `milvus_store.py` 创建/使用集合，负责向量写入和底层相似度检索，并把返回值整理成上层可用的数据。
- `hybrid.py` 组合不同召回方式、应用过滤条件并整理候选结果。需要避免重复块占据候选列表，并保留 Chunk 来源信息。

## 过滤和隔离

来源筛选条件可以用于缩小知识库范围。企业多租户场景还必须把可信的 `tenant_id` 从接口身份传到检索表达式，在向量库检索前过滤；只在召回后筛选会造成越权风险和召回数量不足。数据字段存在或代码支持某个 filter 参数，不能代替跨租户隔离验证。

## 运行依赖与验证

真实检索需要可用的 Milvus 服务、本地嵌入模型及正确的集合结构。更换模型、切分规则或向量维度通常需要重建或版本化索引。检索参数应通过标注相关文档的评测样本比较 Recall@K 等指标，而不是只凭少数手工问题判断效果。
