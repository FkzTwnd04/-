# 问答流程编排

## 在线业务流程

```text
用户问题
  → 简单问候判断
      → 命中：返回通用固定话术
      → 未命中：BM25 检查 MySQL jpkb 热点问答
          → 精确命中或归一化分数 > 0.85：返回该条数据库答案
          → 未命中：Jev 判断问题类型
              → RAG / Agent / AI 专业问题：完整 RAG
              → 通用知识：直接调用大模型
  → 保存会话和运营请求记录
```

专业 RAG 的完整链路是：策略选择、查询改写、Milvus 稠密与稀疏召回、父块整理、重排、证据提示词和模型生成。系统将本轮检索文件名随流式响应返回并显示在回答下方。通用问题不会调用知识库，也不显示来源文件。

## 两个流程文件

- `qa.py`：执行 Jev 分类后的专业 RAG 或通用大模型回答。专业问题负责检索、重排、生成和引用元数据；通用问题构造不带知识库约束的提示词，直接交给大模型。
- `integrated.py`：连接问候处理、`jpkb` 热点问答 BM25、Jev、RAG、会话记录和运营日志。数据库命中后直接返回已有答案；未命中才调用 `qa.py`。

## BM25 热点问答门槛

`storage/subject_qa.py` 从 MySQL `jpkb(subject_name, question, answer)` 读取现有数据。完整问句规范化后完全相同，就按精确命中返回答案。其他问题按 BM25 排序，并使用以下映射把无上限的 BM25 原始分数转换为 0—1 范围：

```text
归一化分数 = BM25 原始分数 / (BM25 原始分数 + 1)
```

只有分数**严格大于 0.85**才直接返回对应数据库答案；等于或低于门槛都算未命中，继续交给 Jev 分类。这是项目当前采用的启发式，不是已被保证的准确率。需要用带正确目标答案和相似负例的评测集衡量误命中，再决定是否调整。

## Jev 路由与失败处理

`jev_classifier.py` 调用 TypeSafe 的 `/v1/systemone` 接口，对“专业 RAG 问题”和“通用大模型问题”两个固定选项作选择。RAG、Agent、AI 及相关工程实践属于专业问题；通用常识、日常问题等走通用大模型。当前置信度门槛为 0.70。Jev API 密钥缺失、调用失败、输出选项异常或置信度过低时，系统回退到完整 RAG。

运行在线 Jev 分类前，需要在本地 `.env` 配置 `JEV_API_KEY`。Jev 不会因为加入系统就自动知道本项目知识库内容；专业问题仍要经过 RAG 检索。

## 回答来源显示

每个知识块在入库时保存原始文件名。RAG 检索后，API 根据块中的文档编号或 `documents` 文档台账补出文件名，并通过 WebSocket 结束消息返回。前端合并重复文件名后展示本轮实际检索文件，不显示 `ai`、`java` 这类资料分类标签。老向量块若没有文档编号，且文档台账也没有对应记录，则需重新摄取原文件才能建立准确的文件关联。

## 结果与限制

- MySQL 命中属于热点问答复用；它不是完整 RAG，也不会显示知识文件来源。
- Jev 仅用于选择问答路线，不能替代大模型回答或专业资料检索。
- 评测应分别查看热点 BM25 误命中、Jev 分类结果、RAG 检索文件和最终回答质量。
- MySQL、Jev、Milvus 或大模型任一依赖不可用，都需要结合 `logs/app.log` 判断是正常未命中还是服务故障。
