# 答案生成

## 模块作用

`generation/` 把用户问题、检索到的资料和提示模板交给大语言模型，生成最终回答。它还提供流式调用，使界面可以在模型尚未生成完整答案时就逐段显示内容。

生成模块只负责构造模型请求和消费模型响应。它不应负责查询数据库、选择检索策略或确定用户是否有权读取资料。

## 生成过程

```text
用户问题 + 会话历史 + 已检索资料
  → prompts.py 组织模型指令和上下文
  → llm.py 调用配置的模型服务
  → 返回完整文本或逐段生成内容
  → pipeline 将结果交给接口层
```

是否把历史加入提示词，应由上层流程根据会话场景控制；检索资料应与用户问题一起明确传入，避免模型只凭参数知识回答本应由知识库支持的问题。

## 文件职责

- `llm.py` 创建模型客户端，封装普通生成和流式生成调用。API Key、服务地址和模型名称从 `base/config.py` 读取；网络错误和服务端错误由调用链捕获处理。
- `prompts.py` 集中定义系统提示、上下文格式和问答模板。将提示集中管理便于统一修改和做评测对比，不应在 API 路由中重复拼接一套提示。

## 引用与拒答的设计要求

非流式 RAG 回答会将检索块标成 `[S1]`、`[S2]` 等编号，提示模型标注依据，并删除上下文中不存在的引用编号；有效引用会连同 Chunk 来源、文档编号、页码和摘要从 `answer_with_details()` 返回。提示词不能保证模型事实正确，引用编号校验也不等于事实支持度校验。流式答案目前尚未做整段引用校验。

## 流式响应注意事项

流式调用返回的是可迭代的文本片段；上层要处理结束标记和异常，避免把字符串当生成器逐字符输出。若生成中途失败，API 层需要告诉客户端回答中断，而不是把不完整答案伪装成正常完成。
