# 评测基线记录

本文件说明如何建立和维护评测基线。**这里不预填任何分数**；分数必须由真实评测报告产生，不能把目标值或示例值冒充运行结果。

## 基线文件

运行器使用 JSON 保存机器可读报告，默认放在：

```text
rag_qa/evaluation/results/baselines/<run-name>.json
```

报告记录数据集路径及 SHA-256、模型名、检索 K 值、上下文候选数、聚合指标和每题结果。建立基线后，不要手动改里面的分数；需要更新时重新运行并使用新的 run name。

## 建立基线的步骤

1. 准备 UTF-8 JSONL 评测集，为问题填写人工核对的参考答案和相关 Chunk ID。
2. 确认 Milvus、模型文件和大模型服务可用，记录当前索引与提示词版本。
3. 运行评测并检查逐题报告，确认失败样本、空检索、异常长回答和明显错答都已处理。
4. 在设置稳定后使用 `--save-baseline` 保存该版本。
5. 后续修改使用同一份数据集运行，并通过 `--compare-baseline` 比较。

## 默认门槛

当前命令行默认允许质量指标绝对下降最多 `0.03`，平均延迟相对增加最多 `20%`。这些只是初始工程门槛，不代表适用于所有业务。积累足够样本后，应按业务风险调整：例如事实查询可以对错答案设置更严格的门槛，长篇生成则不能只靠精确匹配。

回归比较当前覆盖答案精确匹配、字面 Token F1、Recall@K、Precision@K、MRR@K、Hit Rate@K 和平均耗时。缺少人工参考答案或相关 Chunk 标注的指标会被跳过；若新旧报告标注覆盖不一致，应先补齐样本再比较。

## 结果审查原则

- 先看失败样本和误命中案例，再看整体平均数。
- 确认数据集哈希一致；若数据变化，应明确这是新基线或新数据集版本。
- 模型、提示词、索引、切分规则和检索参数要写进变更说明。
- 指标下降时检查样本级检索块和回答，确认是系统退化而非偶然波动。
- 评测门禁只能拦截已覆盖的退化，不能替代人工抽查、接口测试和真实服务监控。
