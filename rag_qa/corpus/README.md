# 文档语料处理

## 模块作用

`corpus/` 把原始文件转换成向量检索可以使用的文本块。文档可能来自 PDF、Word、PPT、图片或普通文本；本模块负责读取内容、保留来源信息、清理和切分文本。它是知识入库的前半段。

语料处理与在线检索分开：语料模块关注“文档怎样变成块”，检索模块关注“给定问题怎样找到块”。解析和 OCR 可能很慢，切分规则也常需要调整；拆开职责可避免修改切分逻辑时把向量库读写混在一起。

## 文档处理流程

```text
文件或目录
  → 根据扩展名选择 loader
  → 提取文本及页码等来源信息
  → 清理内容并按中文规则切分
  → 生成父块/子块等可检索数据
  → 交给检索层写入向量库
```

实际加载格式取决于已安装依赖和对应 loader。扫描 PDF 或图片需要 OCR 支持；文件能被识别不代表 OCR 一定准确，入库前应检查提取结果。

## 目录分工

- `processor.py` 是主入口，根据扩展名选择加载器，调用切分器并整理输出。它负责协调文档解析和切分，不应承担 MySQL 状态机或 API 文件上传逻辑。
- `loaders/` 按文件格式读取正文。`base.py` 定义“一个文件产出一个 Document”的基类；`PdfLoader`、`WordLoader`、`SlideLoader`、`ImageLoader` 分别适配 PDF、Word(.docx)、PPT(.pptx) 和图片；`ocr.py` 提供进程内复用的 OCR 引擎，供扫描页、内嵌图片和图片文件使用。
- `splitters/recursive.py` 的 `ChineseTextSplitter` 按段落、换行、句末标点、分号、逗号的顺序递归切分，标点保留在前一句末尾；`splitters/model.py` 的 `SemanticSplitter` 用本地文档分段模型判断切分位置。
- `dedup.py` 按原始文件内容哈希及稳定来源路径识别新文件、重复文件或同路径更新文件，避免相同文件重复切分和向量化。
- `indexer.py` 登记文档台账、调用解析切分、补全租户/文档元数据、写入 Milvus 并更新成功或失败状态。更新时旧向量的删除与新向量写入并非跨系统原子事务，失败恢复需谨慎处理。

## 父子切分为什么有用

子块较短，检索时更容易精确命中问题相关的段落；父块保留更完整的上下文，生成答案时不容易因为只看到一句断裂文本而遗漏条件。处理时需要保存子块与父块的关联，检索命中后才能返回合适的上下文。

## 输入、输出和边界

输入可以是已有文件/目录或上传服务提供的原始文件；输出是完成文档编号、来源和租户标注的 Chunk。上传 API 属于 `api/`，台账属于 `storage/`，Milvus 写入属于 `retriever/`，任务调度属于 `pipeline/ingest.py`。当前 HTTP 摄取任务队列只存在于单进程内，生产多进程部署需使用持久化共享队列。
