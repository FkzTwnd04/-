# 问题识别与路由

## 在线路由顺序

```text
用户问题
  ├─ 简单问候 → 返回通用的智学答固定话术
  └─ 其他问题
       → storage/subject_qa.py：BM25 查 MySQL jpkb 热点问答
            ├─ 原题精确命中，或归一化分数 > 0.85 → 返回对应数据库答案
            └─ 未命中 → Jev 判断专业问题还是通用问题
                  ├─ RAG / Agent / AI 专业问题 → 完整 RAG
                  └─ 其他问题 → 通用大模型直接回答
```

归一化分数使用 `raw_score / (raw_score + 1)`，将 BM25 原始分映射到 0—1。0.85 是当前的准入门槛，不代表模型准确率；需要通过本项目标注的问题验证。分数没有超过门槛时，不能把排名第一的题库答案直接返回。

Jev 只做分类，不搜索答案，也不写回答。在线运行需要在 `.env` 配置 `JEV_API_KEY`。分类置信度不足或 Jev 服务失败时，系统选择完整 RAG，避免把专业问题误当成通用问题而跳过知识检索。

## 文件职责

- `intent.py`：匹配少数简单问候和身份询问，并返回通用固定话术；其他问题继续正常处理。
- `jev_classifier.py`：调用 TypeSafe Jev，把请求分为“专业 RAG”或“通用大模型”，按置信度门槛安全回退。
- `strategy.py`：只为专业 RAG 请求选择直接检索、HyDE、子查询或回溯等检索策略。
- `classifier.py`：项目原有的 BERT 分类器，保留训练、预测和离线比较能力；当前在线问答由 Jev 负责分类。
- `intent_retriever.py`：使用 BM25 查 `intent_samples` 中的代表问句；不再参与在线主路由，也不使用向量兜底。
- `storage/subject_qa.py`：在线热点问题入口，读取 `jpkb`，精确匹配或 BM25 命中后返回已有答案。

## 评估重点

评测集需要有可复用的热点问题、关键词相似但答案不同的问题、专业问题、通用问题和模糊问题。分别统计数据库误命中率、热点答案覆盖率、Jev 分类准确率、低置信度回退率、请求延迟和大模型调用比例。仅看 BM25 命中数会掩盖错误答案。
