# 检索结果重排

## 模块作用

向量库和稀疏检索负责较快地从大量文档中找出一批候选，但初排顺序不一定完全符合用户问题。重排器对“问题—候选文本”进行更细致的相关性比较，把更有用的资料排在前面，供模型生成答案时优先使用。

## 输入和输出

输入通常包括用户查询、一组候选 Chunk 和需要保留的数量；输出是重新排序后的 Chunk，并附上重排分数。重排器不创建文本、不写向量库，也不应丢掉 Chunk 上的来源和页码等元信息。

## 文件职责

`rerank.py` 加载配置的重排模型，对候选文本评分并处理空列表、候选数量小于目标数量等边界。模型文件位于 `rag_qa/models/bge-reranker-large/`。模型是否能加载取决于本地文件、依赖版本和设备资源。

## 为什么放在召回之后

对整个知识库逐条计算交互式相关性代价太高，所以通常先用检索器快速取 Top-K，再让重排器精排这批候选。召回阶段更重视速度和覆盖，重排阶段更重视局部排序质量。

## 与问答流程的关系

`pipeline/qa.py` 将检索结果交给重排器，再选取少量文本作为生成上下文。重排器应支持关闭或替换，以便做基线比较。评测时要比较重排前后的相关文档排名和最终回答质量，不能只观察分数变化。
