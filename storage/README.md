# 数据存储与知识运营

## 模块作用

`storage/` 管理 MySQL 和 Redis 中的关系数据、会话、答案缓存和运营记录。Milvus 向量检索由 `rag_qa/retriever/` 负责。本目录的 `subject_qa.py` 为在线流程读取项目现有 `jpkb` 热点问答表，并用 BM25 判断是否可直接返回数据库答案。

## 请求经过哪些存储

```text
在线问题 → BM25 检查 jpkb 热点问答 → 高于阈值直接返回数据库答案；未命中再由 Jev 判断走 RAG 或通用大模型
回答完成 → 保存会话 → 写入脱敏请求记录
用户反馈 → 关联请求记录 → 汇总高频未覆盖问题
人工审核候选 → 写入 FAQ → 增加知识库版本，促使旧索引/缓存失效
文档上传 → 按内容哈希登记 → 更新入库状态和失败原因
```

## 文件职责

- `db.py`：创建 MySQL 客户端并提供共享连接。当前不是连接池，多线程或多请求并发时需注意共享游标风险。
- `cache.py`：封装 Redis 连接和基础缓存操作。FAQ 自己管理租户及知识版本缓存键；其他答案缓存准入规则仍需统一。
- `conversations.py`：写入、读取和清理会话记录，默认仅保留最近几轮对话。
- `preprocess.py`：把中文文本转成 BM25 可用的词项；索引内容和查询必须走同一套预处理。
- `documents.py`：记录文档租户、内容哈希、文件位置及摄取状态，支持判断重复/更新文件和失败重试。
- `intent_samples.py`：存储意图代表问句、意图标签及可选标准答案，支持 JSONL 导入和样本停用。
- `subject_qa.py`：读取已有 `jpkb` 问题和答案；精确匹配时直接命中，近似匹配把 BM25 原始分数转换为 `score / (score + 1)`，严格大于 0.85 时返回对应答案。分数未超过门槛就不返回题库答案。
- `faq.py`：从 FAQ 表构建 BM25，未命中时按需使用 BGE-M3 向量余弦；两种检索都要求绝对分和 top1-top2 margin 同时达标，且问题允许静态答案复用。知识版本用于刷新索引和缓存。
- `ops.py`：保存脱敏问题和答案、命中层、意图、耗时与用户评价；把高频问题变成待审核候选，并将人工答案回填 FAQ。

## FAQ 与意图检索的区别

意图代表问句和数据库热点答案是不同的数据。`intent_samples` 保存问题标签，可供离线分析；在线 `subject_qa.py` 使用 `jpkb` 中的真实问题和答案，达到门槛才直接返回答案。FAQ 组件独立管理人工审核的 FAQ，不是当前在线问答的热点答案来源。

项目原有 `jpkb` 表保存 `subject_name / question / answer` 热点问答。在线链路先按规范化问题精确匹配，再检查归一化 BM25 分数是否严格高于 0.85。新增或修改的题库记录在进程缓存刷新后生效。它与 `faq_entries`（独立的人工维护 FAQ）和 `intent_samples`（代表问句和意图标签）用途不同。

## 四级答案复用状态

| 层级 | 作用 | 当前代码情况 |
|---|---|---|
| L1 | 租户和知识版本范围内的精确问句答案缓存 | FAQ 组件内已实现；仍需统一所有业务答案的准入与观测 |
| L2a | FAQ BM25 字面问句检索 | 已实现原始 BM25 分数和 top1-top2 margin 双判据 |
| L2b | FAQ 向量语义相似度检索 | 已实现 BM25 未命中后的按需 BGE-M3 余弦检索；阈值需用标注集校准 |
| L3 | 混合检索、重排和模型生成 | 主要代码已存在；需真实评测确认效果与拒答质量 |

阈值是可配置参数，不是质量保证。上线前需要用本项目人工标注问句校准误命中和覆盖率。

## 知识运营如何运行

1. 问答完成后保存请求记录，手机号、邮箱和身份证号会在日志入库前替换为标记。
2. 响应返回 `request_id`，用户可通过 `/api/ops/feedback` 评价该次回答。
3. `/api/ops/candidates/build` 汇总近期高频 L3 问题。当前只合并标点、空白差异后相同的问题，不做语义聚类。
4. 运营人员查看 `/api/ops/candidates`，人工确认候选是否确实值得补充。
5. 通过审核必须提交人工确认的标准答案；系统写入 FAQ 并递增知识版本。拒绝只更新候选状态，不会发布答案。

## 运行限制

当前默认单租户；没有认证时请求不能安全指定租户身份。MySQL 使用共享连接而不是连接池，运营日志为同步写入且失败时不阻断问答。高并发部署前应改为连接池和异步批量日志写入，并验证所有表、缓存键与 Milvus 查询都受可信租户身份约束。
