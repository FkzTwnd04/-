# 项目测试

## 测试的目的

测试用来确认代码修改没有破坏已有行为。轻量测试检查数据结构、分支处理和模块之间的调用约定；集成测试检查真实数据库、Redis、Milvus 和模型服务能否协同工作；离线评测则比较检索和回答质量。这三类验证解决的问题不同，不能互相替代。

## 已有冒烟测试

`test_pipeline_smoke.py` 通过替身模块屏蔽部分重量级依赖，针对问答编排的若干基本场景运行代码。它适合快速发现导入和流程连接问题，不会真实连接外部服务，也不能证明真实召回率或回答准确率。

## 运行方式

在项目依赖已经安装的 Python 环境中，从仓库根目录运行：

```powershell
python tests/test_pipeline_smoke.py
```

脚本会逐项输出 `[OK]`，最后显示“全部冒烟测试通过”。如果当前环境缺少项目依赖，应先使用项目指定的 Python 环境安装依赖；不要把“因环境缺库无法启动”误判成业务断言失败。

## 逐步补齐的验证层次

1. **纯逻辑测试**：测试 Chunk 转换、文本处理、分数双判据、缓存准入和配置优先级，不需要外部服务。
2. **编排测试**：用假检索器、假模型和假存储验证问答流程，包括命中、未命中、低置信及异常分支。
3. **接口测试**：通过 FastAPI 测试客户端检查请求字段、响应格式、会话和错误处理，并将下游服务替换成测试对象。
4. **集成验证**：在隔离环境连接真实 MySQL、Redis、Milvus 和模型服务，检查写入、检索、会话及流式输出。
5. **质量评测**：使用固定的标注集比较意图、检索、引用和回答质量，并记录延迟及调用成本。

## 意图检索的必要测试

目标方案要覆盖 BM25 命中、BM25 未命中后向量命中、两级都未命中、top1/top2 接近、无代表问句、标准答案不适用以及动态/个人信息问题。每次命中都要验证最终意图和答案是否正确，而不是只验证程序返回了一个标签。阈值变化要在独立验证样本上观察错误直答率，避免只针对训练样本调参。
